# Food Connect

Build a modern, responsive full-stack web application called FoodRescue.

Project Purpose

FoodRescue is a social-impact platform that connects people/businesses with surplus edible food to verified NGOs and community organizations through volunteers. The goal is to reduce food waste and make food redistribution faster and more organized.

User Roles

The application must support four roles:

1. Donor

   

   - Restaurants

   - Hotels

   - College canteens

   - Hostels

   - Event organizers

   - Individuals

2. NGO

   

   - Verified organizations that can request and receive surplus food.

3. Volunteer

   

   - People who can pick up donated food and deliver it to NGOs.

4. Admin

   

   - Manages users, NGO verification, donations, reports and platform statistics.

Landing Page

Create an attractive social-impact landing page.

Hero heading:

"Save Food. Share Hope."

Subtitle:

"FoodRescue connects surplus food with verified organizations and volunteers before it goes to waste."

Primary buttons:

- Donate Food

- Join as Volunteer

Secondary button:

- Find Food

Show impact statistics:

- Meals Rescued

- Food Saved

- Successful Deliveries

Create sections:

- The Problem

- How FoodRescue Works

- Who Can Use FoodRescue

- Our Impact

- Call to Action

Design

Use a clean modern social-impact design.

Requirements:

- Mobile responsive

- Desktop responsive

- Accessible typography

- Clear navigation

- Cards

- Status badges

- Dashboard sidebar

- Attractive but professional UI

- Consistent spacing

- Loading states

- Empty states

- Error states

Use a suitable green/food/environment-inspired visual identity without making the interface overly colorful.

Architecture

Before implementing advanced functionality, create a clean scalable project structure.

Separate:

- UI components

- Pages

- Services/API layer

- Authentication

- Database layer

- Utility functions

- Types/models

- Configuration

Do not implement fake functionality that pretends to work.

For features that are not implemented yet, create appropriate placeholder UI.

Important

Do NOT build all advanced features yet.

This stage is only for:

1. Project architecture

2. Routing

3. UI

4. Responsive layouts

5. Navigation

6. Role-based page structure

7. Reusable components

At the end, make sure the project runs without errors and provide a short explanation of the architecture.
